# Research and architectural decisions

Application development began in a separate empty working folder. The application was subsequently moved into the existing Desktop repository as requested. Its 31 original tracked files, including the condition-specific HTML graphs, were preserved unchanged under `legacy/` and used for the live comparison documented in [LIVE_GROQ_ANALYSIS.md](LIVE_GROQ_ANALYSIS.md).

The pipeline applies inexpensive lexical retrieval first: count every literal occurrence, extract bounded context, merge overlapping windows, deduplicate repeated text, rank by concept coverage and density, and enforce a character-derived token budget. This avoids embeddings and indexes while keeping exact quote provenance. Explicit aliases come from concept review/discovery; local matching does not pretend to understand synonyms semantically.

HTML exports bundle the same graph viewer into an IIFE and embed script-safe JSON plus CSS. They require no CDN or application runtime. Import validation never treats saved quotations as verification against an unavailable original document.

Model presets are editable and account availability is verified only when the user asks to load models. Token estimates are approximate; a dated snapshot of verified provider rates supports approximate costs; unverified prices remain unknown. AI requests are user-initiated and are not retried automatically.

## Groq, compatible providers, and full-paper coverage

Groq remains a dedicated provider using direct browser chat completions, strict structured output for recommended presets and editable model IDs. Its only starter hint is that a free tier is available subject to usage limits. The Cerebras picker and promotional copy were removed; users can use a compatible endpoint, and old drafts are migrated without retaining keys. Known-host pacing still applies through compatible aliases.

Discovery now traverses every parsed body passage in bounded batches; identified bibliography sections are excluded. Explicit keywords are grounded locally; a user description guides the model without becoming automatically generated generic word nodes. Prompts prioritize all named main findings, identifiers and list items, reject bibliography-only concepts and distinguish association from causation. Stable node IDs are assigned locally, so extraction returns only relationships instead of recreating the entire node inventory each time. Grounded isolated nodes remain visible with their sources. Graph caps produce explicit omitted-concept warnings. Whole-paper traversal does not prove that a model identified every important concept.

Keys remain in tab memory and are excluded from storage, exports and diagnostics. The guard estimates the full request, reserves completion tokens, reconciles returned usage, blocks concurrency/rejected keys, and waits under minute/day budgets. Provider response headers and Retry-After can extend waits. Other applications, tabs, organization usage and exact tokenization remain outside its view. See [Groq rate limits](https://console.groq.com/docs/rate-limits) and [the measured evaluation](LIVE_GROQ_ANALYSIS.md).

The viewer supports circular or card nodes with wrapped labels, distinct colors, repulsion, longer springs and collision resolution. Dense graphs open at a readable zoom with explicit overview and zoom controls. PNG/SVG exports contain the full graph; standalone editable HTML contains the same local viewer and no provider calls. Evidence preserves PDF page indices, paragraph IDs and the actual quote even after user edits.

The multi-paper workflow namespaces passage IDs by uploaded file, preserves per-paper page/paragraph identity, and retains separately cited corroborating relationships. Each node keeps up to five matched source paragraphs per paper. Automatic OCR failures exclude unreadable pages/files while retaining recovered text. Live graph updates and usage receipts are local, deterministic UI work; only concept/relationship reasoning invokes an LLM. See [the implementation and verification report](MULTI-PAPER-WORKFLOW.md).

## Unified workspace and visual redesign

The homepage remains a separate introduction; the research workspace now shows uploads, optional focus/keywords, provider/model/key and the run estimate together. This replaces the prior step wizard. Advanced context and connection settings remain optional disclosures; history remains a paginated dialog. Desktop setup is compact without clipping required controls, while smaller screens retain natural vertical flow.

The charcoal/warm-paper palette, editorial typography and original CSS research constellation were informed by the local PenSpectra project’s dimensional presentation. The scene uses CSS geometry, optional pointer depth and reduced-motion support without a 3D engine. Native Cytoscape gradients add depth to graph nodes; existing label-aware spacing, collisions and evidence inspection remain functional. Offline HTML uses the same palette and bundles its third-party license notice.

Discovery and extraction instructions now describe domain-appropriate concepts and predicates rather than a fixed biomedical ontology. A biomedical feature-list safeguard is conditional on biomedical excerpts. Generic categories, stable identifiers and exact source quotes support other research disciplines. New astrophysics, materials and social-science fixtures verify grounding and validation; they do not replace the earlier measured live Groq evaluation.

The original code uses permission-required terms because the owner explicitly requested written approval before reuse. Hosted-app use and graph sharing are permitted by the export exception; dependency terms remain separate. The build carries notices and the HTML viewer preserves Cytoscape’s MIT notice. See [CODE-USE-PERMISSION.md](CODE-USE-PERMISSION.md).
